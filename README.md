# 臺北市政府常見問答 · 爬蟲工作台

把 [市府官網「常見問答」](https://www.gov.taipei/News.aspx?n=EEC70A4186D4C828&sms=87415A8B9CE81B16)
全站 8,300 多筆抓下來，存成一份 JSON，附一個網頁工作台可以查詢、分析、
產出給各局處的維護清單。

**官網有幾筆，這裡就是幾筆** —— 每次抓完都會對帳並印出
「站上 N 筆　已下載 N 筆　★ 一致」。

---

## 搬到另一台電腦

### 1　裝 Python

到 <https://www.python.org/downloads/> 下載安裝，
**安裝時一定要勾「Add python.exe to PATH」**，不然批次檔叫不到它。

### 2　把整個資料夾複製過去

隨身碟、雲端硬碟都行。整包約 47 MB。

或用 git（兩台電腦之後要同步的話建議這個）：

```bash
git clone https://github.com/andy939/faq-crawler.git
```

### 3　裝套件

```bash
pip install requests openpyxl
```

`requests` 是必要的；`openpyxl` 只影響 Excel 匯出。

### 4　環境檢查

雙擊 `啟動.bat` 之前，先確認這台電腦連得到、沒被擋：

```bash
python crawl.py --check
```

八項全部 OK 才往下走。公司網路常見的兩個問題在最下面「必記的坑」第 9、10 點。

### 5　開始用

雙擊 **`啟動.bat`** → 瀏覽器自己開 <http://127.0.0.1:8765>

不想每次都點，雙擊一次 **`設定開機自動啟動.bat`**，以後開機就有，
只要開瀏覽器（或雙擊 `docs\index.html`）就能用。

## 網頁工作台

左邊七個分區，點哪個顯示哪個。左上角的 `‹` 可以把選單收起來讓內容變寬。

| 分區 | 做什麼 |
|---|---|
| **問答查詢** | 關鍵字（標題＋內容＋機關）、局處分類、年份、只看有附件 |
| **資料清單** | 一筆一列、每個欄位都列出來、可排序、匯出 Excel |
| **爬蟲工具** | 上面是**雲端抓取**（在 GitHub 執行、倉庫連結、最近幾輪雲端執行的狀態，公司和手機也看得到）；下面是**本機抓取**（選抓法／模式／筆數／日期／限速）與工具按鈕，只有本機工作台才出現 |
| **資料概況** | 機關分布、年份分布、下版日期維護、內容長度、位元效率 |
| **維護建議** | 要發給各局處的待修正清單，可依機關拆開匯出；點長條會替你篩選，「✕ 清除篩選」一鍵回到全部 |
| **執行紀錄** | 歷次測試比較表，第一欄是「開始 → 結束」（舊紀錄沒記開始的，用結束減耗時推回去，標「約」） |
| **異動紀錄** | 逐筆的新增／異動／下架／復原 |

**搜尋**用空白分隔多個詞，每個詞都要出現（不限順序、不限位置）——
不知道站上用什麼專有名詞時就拆開打，「生理 用品」找得到「生理用品」。

**表格**點欄位標題就排序，再點一次反向。排的是整份資料不是畫面上那幾列。

**匯出一律是 Excel**（欄寬自動、第一列凍結並開篩選、數字是真的數字）。
GitHub Pages 上沒有本機工作台，會自動退回 CSV。

## 抓取

爬蟲工具那頁選好按「開始抓取」，或用命令列：

| 模式 | 做什麼 | 時間 |
|---|---|---|
| **全站重抓** | 8,300 多筆全部重抓，抓得到所有異動 | 約 1.5～2 小時（E・併發 3） |
| **補齊** | 抓完整清單比對，只補缺的 | 20 秒 ~ 3 分 |
| **RSS 快更** | 只抓官方 RSS 說有異動的那幾筆 | 數秒 |
| 補齊＋複查 N 筆 | 補齊之外再輪流複查舊資料 | 2 ~ 5 分 |

```bash
python crawl.py --full           # 全站重抓
python crawl.py                  # 補齊
python crawl.py --rss            # RSS 快更
python crawl.py --method E --limit 500   # 效能測試
python crawl.py --check          # 環境檢查
```

**中途可以按「停止」**，已抓到的會存檔，下次補齊會接著補。
關掉網頁不影響抓取（真正在跑的是背後的工作台）。

**官網整個沒反應時會自己停**（本機和 GitHub 一樣，寫在 `crawl.py`）：
連續 1 分鐘沒拿到任何一筆正常頁，就「停 1 分鐘、試 1 分鐘」輪流，停的時候
完全不送請求；中間只要有一筆正常就回到平常的抓法；連續 30 分鐘都失敗就自動
停止，runs.csv 備註記「官網 30 分鐘沒有回應，自動停止」。每次開始停、再試、
恢復、放棄，紀錄框都會印一行 `！！【告警 時間】…`。
2026-09-26 官網 19:54 掛掉，沒有這個機制時爬蟲白白重試了 3 小時、6,268 次。

### 哪一種抓得到「內容被改了」

| | 抓得到嗎 |
|---|---|
| 全站重抓 | **全部** |
| RSS 快更 | 官方 RSS 報的那 50 筆之內 |
| 補齊 | **抓不到** —— 它只補手上沒有的 |

官網清單只印發布日期、不印更新時間，所以不進去敲內文頁就不知道誰改了。
RSS（`OpenData.aspx?SN=46F4BC0B817F916D`）的 `pubDate` 是更新時間，一次請求
就知道最近誰動過 —— 但只有 50 筆，當日異動超過 50 筆會漏，所以是快篩不是保證。
程式發現「RSS 最舊的一筆比你上次跑的還新」時會提醒你補跑全站。

### 「官網幾筆就抓幾筆」怎麼保證

每次都先把整份清單抓下來（42 頁、約 48 次請求），拿站上自己印的總筆數當基準：

1. 清單有、我們沒有 → 抓進來
2. 清單有、上次沒抓成功 → 補抓
3. 我們有、清單沒有 → **不直接當下架**。清單是活的，抓那兩分半裡順序會位移，
   有筆從第 34 頁擠到第 33 頁就會被漏看。所以逐筆去敲它的內文頁確認，
   還開得起來就是還在，開不起來才標下架（資料保留，只是不列入計數）

**外部連結的 key 要用「網址＋標題」**：站上有兩筆不同的問答連到同一個外部
網址，只用網址當 key 會併成一筆，筆數就永遠比官網少一。

### 總筆數一樣不代表沒事

可能今天新增一筆、同時下架一筆。所以每次都逐筆跟前一版比對，
新增／異動／下架／復原記進 `docs/changes.csv`，異動還註明改了哪個欄位
（內容 +312 字、附件 +1、下版日期…）。

比對基準是「那一筆目前存的內容」，不是「上次執行的時間」。
所以同一天抓十次、內容沒變，異動紀錄一列都不會增加。

實際跑起來，異動有 99% 只是時間戳變動（市府系統碰一下資料，檢視時間就跳，
內容沒動），所以異動紀錄那頁**預設只看實質變動**。

## 抓法 A~F（效能比較用）

| 抓法 | 說明 |
|---|---|
| A | 每筆重開連線（沒用 Session），最慢 |
| B | 直接抓・循序 |
| C | 同 B 但關掉 gzip，用來看壓縮省了多少 |
| D | 完整瀏覽器流程（cookie + Referer + 點閱回報） |
| **E** | **直接抓・併發 3 ★建議** |
| F | 直接抓・併發 8 |

每次執行都會留下逐筆原始測量到 `exports/`（一次執行 × 一筆各一列），
包含等伺服器／傳輸／解析分段計時、抓下／原始／需要三種位元數、
thread 歸屬，以及**錯誤頁與失敗也會留一列**（分析限流要用）。

`docs/faq.json` 會被後續執行覆蓋，`exports/` 不會 ——
想到新的分析角度重算就好，不用重爬。

## 限流：觀察到的現象（不是結論）

站方會對抓太多的 IP 加罰約 2 秒 TTFB，或直接回 3 KB 錯誤頁。

**能確定的**：它會來會走、會自行解除、白天和辦公室網路特別容易中。
提過的四個假說（不重用連線才會被罰、約 500 筆觸發、3 條連線會觸發、
晚上就安全）全部被自己的資料推翻。

**設定什麼就抓什麼，程式不會自己判斷要不要跑。** 開跑前會探 5 筆並印出
每一筆的「等伺服器」毫秒，但那只是報數字，不攔人（要恢復舊行為加 `--gate`）。
保護資料的是這三道，看的是實際發生什麼：

1. 拿到錯誤頁一律當沒抓到，絕不寫進去覆蓋好資料
2. 空內容不覆蓋既有內容
3. 連續拿到錯誤頁才停（預設 0 ＝ 不自動停，要停用 `--abort-after N`）

「被擋」和「官網掛掉」是兩回事：擋是站方還在、只是不給抓；掛是什麼都不回。
後者由上面「停 1 分鐘、試 1 分鐘、30 分鐘放棄」處理。

## 資料

| 檔案 | 內容 |
|---|---|
| `docs/faq.json` | **資料本體**，一筆一行的 JSON 陣列 |
| `docs/faq_html.json` | 原始 HTML（超連結、表格、換行靠它還原） |
| `docs/changes.csv` | 逐筆異動紀錄 |
| `docs/runs.csv` | 每次執行的彙總：開始時間、結束時間（到分鐘）、耗時、每筆、壓縮率、有效率… |
| `docs/meta.json` | 現況摘要 |
| `docs/conflicts.json` | 跨條文數字不一致、電話位數不對（`conflicts.py` 每次抓完自動重算） |
| `exports/*.csv` | 逐筆原始測量。檔名是「開始-結束_方法X_N筆.csv」；帶 BOM，Excel 直接開不會亂碼 |

每筆的欄位：

| 欄位 | 說明 |
|---|---|
| `sid` | 站內 16 碼 HEX；外部連結是 `EXT:網址\|標題` |
| `title` `dept` `answer` | 標題、發布機關、內文純文字 |
| `published` `updated` `reviewed` `expire` | 發布、更新、檢視、下版日期（西元） |
| `maintainer` | 資料維護單位 |
| `files` | 附件陣列：`name` `kind` `size` `url` |
| `bytes_wire` `bytes_raw` `bytes_needed` | 抓下（gzip 後）／原始 HTML／真正需要 |
| `url` `kind` | 網址、`internal` 或 `external` |
| `gone` | 只有已下架的才有，值是確認下架的日期 |

**刻意不存**序號和抓取時間 —— 那兩個每次抓都會變，
存了的話每次 commit 都是八千行全改。

一筆一行是為了讓 git 只記下真的有改的那幾行。

## 雲端執行（GitHub Actions）

用 GitHub 的機器去抓，不占用你的電腦和你的 IP，抓完自動 commit 回 repo，
約 1 分鐘後 GitHub Pages 上的工作台就看得到新資料。
實測 GitHub 的美國 IP **沒有**被市府網站擋。

**手動**：工作台「爬蟲工具」→「在 GitHub 執行 ↗」→ Run workflow ▾ → 選模式 → Run workflow。
在公司、手機打開 `andy939.github.io/faq-crawler/` 也能用。

**每天自動：臺北 07:00 全站重抓**（抓法 E・併發 3，約 1.5 小時，時間上限 300 分鐘）。
為什麼每天全站：官網清單只印發布日期、不印更新時間，局處改了既有問答
從清單上看不出來，只能逐筆打開比對。

```
每天 07:00（臺北）
 ├─ Cloudflare Worker「faq-crawler-trigger」（準時）── API ──▶ GitHub Actions 全站重抓
 └─ GitHub 自己的排程（常延後一兩個小時，當備援）
       └─ 開跑前看 meta.json 的 last_full：今天已完整全站過 → 跳過；沒有 → 補跑
```

- GitHub 自己的排程很不準（設 22:00，實際凌晨 1～3 點才跑），所以主要由
  Cloudflare 的 Cron Trigger 觸發。程式在 `cloudflare/trigger-worker.js`，
  設定步驟寫在檔案開頭。Cloudflare 上的 Cron 是 `0 23 * * *`（UTC 23:00 ＝ 臺北 07:00）。
- Worker 用的 GitHub 權杖存在 Cloudflare 的 Secret `GITHUB_TOKEN`：fine-grained、
  只給 faq-crawler、權限只有 Actions: Read and write。**權杖會過期**，到期後
  Cloudflare 觸發會失敗，但 GitHub 的備援排程仍會跑（只是晚一點）。
- `last_full` 只有全站「沒被中斷」跑完才會寫，中斷的那輪不算，備援會補跑。
- checkout 取「開跑當下」最新的 main，排隊等前一輪的那一輪不會拿舊資料開跑。
- 雲端抓完**不會**同步秘密客與 FAQ 搜尋站，那要在本機跑「同步到網站」。
- Cloudflare 上另一個 Worker `taipei-news-trigger` 是觸發 Taipei_NEWS 的，跟這裡無關。

網頁也可以從 GitHub Pages 驅動你本機的工作台 —— 瀏覽器雖然禁止 https 網頁
連 http 網站，但 `127.0.0.1` 是例外。放行清單在 `工作台.py` 的 `ALLOW_ORIGINS`。

## 必記的坑

**1　被擋時是 HTTP 200 + 3 KB 錯誤頁**

正常內文頁約 197 KB。只看狀態碼會把錯誤頁當正常內容解析（解出空字串）
寫進資料 —— 這個 bug 曾經把 5,947 筆好內容覆蓋成空的，而且完全不會報錯。
用 `faqlib.is_blocked()`：狀態碼不對、頁面小於 50 KB，一律當作沒抓到。

**2　空內容不可以覆蓋既有內容**

`crawl.merge()` 裡那段。寧可留舊的，也不要靜靜地把資料弄不見。

**3　清單解析不能用跨列的 regex**

清單混著連到外部網站的項目，跨 `<tr>` 的 `.*?` 會把後面那筆一起吃掉。
第一版少了 40 筆，不會報錯，只會靜靜少資料。要先切 `<tr>` 再逐列解析。

**4　站方對超出範圍的頁碼一直回最後一頁**

page=43、44、60 都回同樣的最後一頁。不能靠「翻到沒東西」判斷結束，
會無窮迴圈（曾經白打 353 次請求）。要先讀站上印的總筆數算頁數。

**5　清單分頁會重複**

清單是活的，同一筆會出現在相鄰兩頁。要依 sid 去重，不然筆數會灌水。

**6　內文空白不代表抓失敗**

有些問答的答案本身就是一份 PDF 附件，也有些站上本來只建了標題沒填內容。
判斷「有沒有抓到」要用**有沒有標題**（錯誤頁沒有 `og:title`），
不能用「有沒有內文」。統計「有內容」則要算 `answer 或 files 至少有一個`。

**7　民國年字串不能直接排序**

`96-01-01` 和 `115-09-08` 字典序會顛倒。存進 JSON 前一律用 `crawl.iso()`
轉成西元。

**8　「最後檢視」不能拿別的日期頂替**

站上沒填檢視時間的（39 筆外部連結）如果退而用發布時間，它們會看起來像
「發布那天被檢視過」，然後全部被判成「一年以上沒檢視」。只認站上真正的
`資料檢視` 欄位。

**9　Python 連這站會 SSL 錯誤**

```
CERTIFICATE_VERIFY_FAILED: Missing Subject Key Identifier
```

不是憑證有問題，是 OpenSSL 3.x 的 RFC5280 嚴格模式。
`faqlib.ssl_context()` 已處理（只關掉那個吹毛求疵的旗標）。
**不要改成 `verify=False`**，那是真的把中間人防護關掉。

**10　公司電腦的 TLS 攔檢**

公司做 TLS 攔檢會讓連線整個失敗。跟資訊單位要根憑證，設環境變數
`REQUESTS_CA_BUNDLE` 指到它。一樣不要用 `verify=False`。

**11　Windows 主控台是 cp950，印繁體中文會爆**

`faqlib.py` 開頭已處理。批次檔也加了 `chcp 65001`。

**12　探測不能把自己的成本算進去**

量「站方是不是在限流」只能量等伺服器那一段。把限速器的 sleep、
第一次連線的 DNS/TLS 握手、197 KB 內文的下載時間算進去的話，
在公司第一次跑幾乎每次都會誤判成被限流。

**13　答案裡會夾帶網頁樣式碼**

承辦從 Word 或別的網頁複製貼上時，內文 HTML 會混著 `<style>…</style>`、
`<script>…</script>`（法規元件、Google 地圖）和 `<!-- … -->` 註解。只拿掉標籤的話，
中間的 CSS 會原封不動留在答案開頭（例如 `p, li { white-space: pre-wrap; } …`）。
`faqlib.clean_text()` 去標籤前會先整段刪掉這三種。2026-09-26 修正時影響 45 則，
用 `docs/faq_html.json` 重算即可，不用重爬。

**14　GitHub 的排程會被擠掉**

同一個 workflow 有兩個排程、又都延後到差不多的時間時，GitHub 只留一班在排隊，
另一班會被取消（2026-09-20 週日的全站就這樣沒跑）。現在只剩一班排程，
主要靠 Cloudflare 準時觸發。

**15　行內標籤不能換成換行**

去標籤時如果每個標籤都換成換行，粗體、連結、顏色字會把一句話切成好幾行
（「為期<strong>101</strong>天」→「為期／101／天」），搜尋跨過斷行的字也找不到。
只有區塊標籤（`p` `br` `li` `tr` `div`…）才換行，表格同一列用空白隔開，其他直接拿掉。
