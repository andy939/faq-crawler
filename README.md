# 臺北市政府常見問答 爬蟲 · 工作台

抓 [市府官網「常見問答」](https://www.gov.taipei/News.aspx?n=EEC70A4186D4C828&sms=87415A8B9CE81B16)
全站約 8,300 筆，存成一份 JSON 跟著 git 走，
GitHub Actions 定時更新，GitHub Pages 有一個查詢兼評估的網頁工作台。

**網頁**：`https://<你的帳號>.github.io/<這個 repo 的名字>/`
（推上 GitHub 後，Settings → Pages → Source 選 `main` 分支 `/docs` 資料夾）

---

## 整包只有五個檔案

| 檔案 | 用途 |
|---|---|
| `crawl.py` | 爬蟲。抓取、比對、寫資料、記錄耗時，全部在這裡 |
| `faqlib.py` | 站台常數與 HTML 解析。**要改解析邏輯就改這一個檔案** |
| `工作台.py` | 本機伺服器。讓網頁上的按鈕可以真的按下去抓（雙擊 `啟動.bat` 就是跑它） |
| `docs/index.html` | 網頁工作台（查詢、概況、維護建議、執行紀錄、異動紀錄） |
| `docs/faq.json` | **資料本體**。8,304 筆，一筆一行 |
| `.github/workflows/crawl.yml` | GitHub 上的自動與手動執行 |

`docs/` 底下另外兩個檔案是程式自己寫的：`meta.json`（現況摘要）、
`runs.csv`（每次執行的耗時紀錄）、`changes.csv`（逐筆異動紀錄）。

## 三種跑法

### 1　在 GitHub 按按鈕（平常用這個）

repo 的 **Actions** 分頁 → 左邊選「更新 FAQ」→ 右邊 **Run workflow** →
選模式 → 綠色按鈕。跑完會自動把資料 commit 回 repo，網頁隨即更新。

三種模式：

| 模式 | 做什麼 | 大約要多久 |
|---|---|---|
| 補齊 | 抓完整清單比對，**站上有幾筆就補到幾筆** | 20 秒 ~ 3 分 |
| 補齊＋複查 300 筆 | 再輪流複查 300 筆舊資料，抓得到舊資料被改 | 3 ~ 5 分 |
| 全站重抓 | 8,300 筆全部重抓一遍 | 約 50 分 |

**「補齊」抓不到內容變動。** 官網清單只印發布日期、不印更新時間，
所以既有問答的內文被改了，不去敲內文頁根本看不出來。要靠複查和全站重抓。

跑完在該次 run 的頁面下方有「抓取結果」摘要，直接寫著站上幾筆、抓到幾筆。

### 2　排程自動跑

- 每天 22:00（臺北）補齊＋複查 500 筆（約 17 天輪完全站）
- 每週日 23:00（臺北）全站重抓一遍（保證內容變動最慢 7 天會發現）

時間挑晚上是有原因的，見下面「限流」。

### 3　本機跑

```bash
pip install requests
python crawl.py            # 補齊
python crawl.py --full     # 全站重抓
python crawl.py --check    # 環境檢查，到新電腦先跑這個
python crawl.py --dry-run  # 只看會做什麼，不寫檔
```

跑完 commit + push，GitHub 上的網頁就更新了。

**雙擊 `啟動.bat`** 會開本機工作台 <http://127.0.0.1:8765>，
跟 GitHub Pages 上是同一個網頁，但多一塊**本機控制台**：
選模式、按「▶ 開始抓取」，抓取進度即時顯示在網頁上，跑完按重新載入就看到新資料。
（GitHub Pages 上沒有這塊 —— 靜態網頁沒有後端，按不動。）

## 「官網幾筆就抓幾筆」是怎麼保證的

每次都先把**整份清單**抓下來（42 頁、約 48 次請求、十幾秒），
拿站上自己印的總筆數當基準，然後：

1. 清單有、我們沒有 → 抓進來
2. 清單有、我們有但上次沒抓成功 → 補抓
3. 我們有、清單沒有 → **不直接當下架**。清單是活的，抓那兩分半裡順序會位移，
   有筆從第 34 頁擠到第 33 頁就會被漏看。所以逐筆去敲它的內文頁確認，
   還開得起來就是還在，開不起來才標下架（保留資料，只是不列入計數）
4. 最後印出「站上 N 筆　已下載 N 筆　★ 一致」

**外部連結的 key 要用「網址＋標題」**。站上有兩筆不同的問答
（殯葬處那兩筆）連到同一個外部網址，只用網址當 key 會併成一筆，
筆數就永遠比站上少一。

### 內容被改了怎麼發現

清單看不到更新時間，所以只有**真的去敲內文頁**才知道內容變了。
兩道防線：每天輪流複查 500 筆（約 17 天輪完），每週日全站重抓（最慢 7 天）。
一發現不一樣就記進 `docs/changes.csv`，還會註明是哪個欄位變的。

### 總筆數一樣不代表沒事

可能今天新增一筆、同時下架一筆。所以每次抓取都逐筆跟前一版比對，
新增／異動／下架／復原全部記進 `docs/changes.csv`，
異動還會註明是哪個欄位變了（內容 +120 字、附件 +1、下版日期…）。

## 網頁工作台

| 分頁 | 內容 |
|---|---|
| 問答查詢 | 關鍵字（標題＋內容）、機關、年份、只看有附件、匯出 CSV |
| 資料概況 | 機關分布、年份分布、下版日期維護、內容長度 |
| **維護建議** | **要發給各局處的待修正清單，可依機關拆開匯出 CSV** |
| 執行紀錄 | 每次跑的耗時、每筆毫秒、請求數、被擋次數、下載量 |
| 異動紀錄 | 逐筆的新增／異動／下架／復原 |

維護建議的六種問題：已過期還掛著、沒設下版日期、一年以上沒檢視、
沒有內容、連到外部網站、標題重複。一列一個問題，匯出的 CSV
可以直接按機關拆給承辦。

## 限流：觀察到的現象（不是結論）

站方會對抓太多的 IP 加罰約 2 秒 TTFB，或直接回錯誤頁。

**能確定的**：它會來會走、會自行解除、白天和辦公室網路特別容易中。
提過的四個假說（不重用連線才會被罰、約 500 筆觸發、3 條連線會觸發、
晚上就安全）全部被自己的資料推翻，所以不再提新假說。

程式的對策：

- 開跑前先探測 5 筆，中位數超過 800ms 就**直接跳過這次**，不硬衝
  （`--force` 可以蓋過去）
- 連續被擋 5 次就整個停下來，已抓到的存檔，下次接著補
- 全域限速 333ms 一次請求，含抖動

GitHub Actions 跑的時候，站方看到的是微軟 Azure 的美國 IP，
跟你家／公司的 IP 各算各的額度。**如果發現 Azure IP 整個被擋**，
退路有兩條：本機跑完 push，或在自己的電腦上裝
[self-hosted runner](https://docs.github.com/actions/hosting-your-own-runners)，
這樣 GitHub 上的按鈕就變成「叫你自己那台電腦去爬」。

## 必記的坑

**1　被擋時是 HTTP 200 + 3 KB 錯誤頁**

正常內文頁約 197 KB。只看狀態碼會把錯誤頁當正常內容解析（解出空字串）
寫進資料 —— 這個 bug 曾經把 5,947 筆好內容覆蓋成空的，而且完全不會報錯。
用 `faqlib.is_blocked()`：狀態碼不對、頁面小於 50 KB，一律當作沒抓到。

**2　空內容不可以覆蓋既有內容**

`crawl.merge()` 裡那段。寧可留舊的，也不要靜靜地把資料弄不見。

**3　清單解析不能用跨列的 regex**

清單混著連到外部網站的項目，跨 `<tr>` 的 `.*?` 會把後面那筆一起吃掉。
第一版少了 40 筆，不會報錯，只會靜靜少資料。要先切 `<tr>` 再逐列解析。

**4　站方對超出範圍的頁碼一直回最後一頁**

page=43、44、60 都回同樣的最後一頁。不能靠「翻到沒東西」判斷結束，
會無窮迴圈（曾經白打 353 次請求）。要先讀站上印的總筆數算頁數。

**5　清單分頁會重複**

清單是活的，同一筆會出現在相鄰兩頁。要依 sid 去重，不然筆數會灌水。

**6　內文空白不代表抓失敗**

有些問答的答案本身就是一份 PDF 附件，也有些站上本來只建了標題沒填內容。
判斷「有沒有抓到」要用**有沒有標題**（錯誤頁沒有 `og:title`），
不能用「有沒有內文」。統計「有內容」則要算 `answer 或 files 至少有一個`。

**7　民國年字串不能直接排序**

`96-01-01` 和 `115-09-08` 字典序會顛倒。存進 JSON 前一律用 `crawl.iso()`
轉成西元。

**8　Python 連這站會 SSL 錯誤**

```
CERTIFICATE_VERIFY_FAILED: Missing Subject Key Identifier
```

不是憑證有問題，是 OpenSSL 3.x 的 RFC5280 嚴格模式。
`faqlib.ssl_context()` 已處理（只關掉那個吹毛求疵的旗標）。
**不要改成 `verify=False`**，那是真的把中間人防護關掉。

**9　公司電腦的 TLS 攔檢**

公司做 TLS 攔檢會讓連線整個失敗。跟資訊單位要根憑證，設環境變數
`REQUESTS_CA_BUNDLE` 指到它。一樣不要用 `verify=False`。

**10　Windows 主控台是 cp950，印繁體中文會爆**

`faqlib.py` 開頭已處理。

## 資料格式

`docs/faq.json` 是一個 JSON 陣列，**一筆一行**（所以 git 只會記下真的有改的
那幾行，倉庫不會愈長愈肥）。每筆的欄位：

| 欄位 | 說明 |
|---|---|
| `sid` | 站內 16 碼 HEX；外部連結是 `EXT:網址\|標題` |
| `title` `dept` `answer` | 標題、發布機關、內文純文字 |
| `published` `updated` `reviewed` `expire` | 發布、更新、檢視、下版日期（西元） |
| `maintainer` | 資料維護單位 |
| `files` | 附件陣列：`name` `kind` `size` `url` |
| `url` `kind` | 網址、`internal` 或 `external` |
| `gone` | 只有已下架的才有這個欄位，值是確認下架的日期 |

**刻意不存**序號（`no`）和抓取時間 —— 那兩個每次抓都會變，
存了的話每次 commit 都是八千行全改。

舊的 `faq.db`（SQLite，含效能實驗的 12 萬列 `samples`）已經不再使用，
留在本機當備份，不進版本控制。

## 兩台電腦怎麼同步

裝 [GitHub Desktop](https://desktop.github.com)，兩邊登入同一個帳號，
clone 同一個 repo。改完一邊 Commit + Push，另一邊 Pull。
**資料也跟著 git 走**，不用再搬 zip、不用再傳資料庫。

GitHub Actions 自己 commit 的時候，你下次 Pull 就拿到最新資料了。
